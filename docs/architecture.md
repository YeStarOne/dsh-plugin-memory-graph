# 架构

memory-graph 把「聊天记录」变成「会遗忘的图谱」，分写入与读取两条管线。

```
写入（后台，不阻塞对话）                                读取（每条入站消息一次）
┌──────────────┐   ┌───────────────────────────┐      ┌──────────────┐
│ user/reply 对 │→ │ ① 事实抽取   对话→事件+实体  │      │ 当前用户消息   │
│ (turn 级捕获) │  ├───────────────────────────┤      └──────┬───────┘
└──────────────┘  │ ② 概念归纳   实体→概念标签   │             ↓ embed(1次调用)
   攒 batchSize   ├───────────────────────────┤      ┌──────────────┐
   轮触发          │ ③ 实体关系   src-REL-dst    │      │ 向量召回 top10 │
                  ├───────────────────────────┤      └──────┬───────┘
                  │ ④ 事件关系   时序/因果五类   │             ↓ 沿边走 4 跳
                  └─────────────┬─────────────┘      ┌──────────────┐
                                ↓                    │ 子图扩展 ≤30点 │
                     ┌─────────────────┐             └──────┬───────┘
                     │ nodes/edges.jsonl│                    ↓
                     │ （追加+墓碑+压实） │             ┌──────────────┐
                     └─────────────────┘             │ 加权重排 → top5│
                                                     │ 0.5相似+0.3重要│
                        每天 maintain()：             │ +0.2新近(+0.3钉)│
                        衰减/裁剪/压实                └──────┬───────┘
                                                              ↓
                                                    [以下为系统信息…]-事件(时间)
                                                     拼在系统提示前，随回合发走
```

## 四阶段抽取

每批（默认 2 轮）对话触发 2~4 次 LLM 调用：

1. **事实抽取**：LLM 从对话里提出「事件」——完整的一件事（谁/做了什么/结果），打 0~1 重要度，并列出参与实体（只收具体名词，代词必须还原）。
2. **概念归纳**：给每个新实体贴 1~5 个抽象类目标签（妈妈→家人）。**优先复用已有概念池**，防止概念池无序膨胀。
3. **实体关系**（默认关）：实体对之间的语义关系，relation 强制 `SCREAMING_SNAKE_CASE`。
4. **事件关系**（默认关）：事件间的 `BEFORE/AFTER/AT_SAME_TIME/BECAUSE/AS_RESULT` 五类时序因果。

所有阶段对 LLM 输出做宽松解析（容忍代码围栏/废话/尾随逗号），解析失败把错误回喂重试一次，仍失败降级为「本批不入库」——记忆管线坏掉绝不能弄崩对话。

## 事件去重与合并

入库前按归一化文本（去空白/标点/大小写）查重：同一事件再次发生时**不新建节点**，而是提升已有节点重要度、刷新时间、`instanceCount+1`。「常一起做的事」自然越来越牢。

## 检索：向量 + 图混合

- 只检索 `event` 节点（实体/概念负责建图与扩展，不直接进提示词）
- 相似度门限（默认 0.25）作用在事件自身与查询的相似度上
- 图扩展把「与命中事件有关系」的邻居也捞进来（4 跳、上限 30 点），再统一过门限
- 重排是加权和，`custom` 标记（"这条不许忘"类钉住）额外 +0.3
- 被召回即刷新 `lastUsedAt`——热记忆在衰减与裁剪里更安全

## 遗忘

`maintain()`（建议每天一次）：

- **衰减**：30 天半衰期指数衰减 importance；新记忆 7 天宽限期；低于 0.2 删除；`custom` 永不衰减
- **裁剪**：概念池上限 1000，按冷热淘汰；事件/实体不按数量裁
- **压实**：墓碑占比 >0.3 时重写 JSONL

## 每聊天分库 + 会话隔离

数据根目录下每个 chatId 一个独立子库。桥接层只捕获真实用户回合：虚拟/场景回合（`adoptedLifeTurn` 标记的虚构内容）跳过捕获与召回——虚构对话一旦被抽成「用户说…」的事件，就是长期记忆里最难清的污染。

## 回复捕获的层级选择

在 session 事件层捕获完整回复（`assistant/message`，按 message.id 去重），而不是投递层——下游的气泡拆分/TTS 分段只看到碎片，上游才是完整语义单元。`turn/end` 且 `completed` 才配对入库；出错/取消的回合两侧一起丢弃。

## 存储格式

JSONL 追加日志：更新=追加新版本行（后写覆盖先写），删除=墓碑行；加载时重建内存索引并丢弃悬空边；原子写（临时文件+rename）。好处：零依赖、崩溃安全、`cat` 可读、拷目录即备份、git diff 一目了然。
