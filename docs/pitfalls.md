# 坑与经验（按踩到的概率排序）

这套东西在真实 7×24 QQ 机器人上跑通过，下面是踩过的坑，多数从表面完全看不出来。

## 1. 向量模型的「中文塌缩」——连通性正常，检索等于没做

某些 embedding 模型对中文把所有句子映射到球面上很近的位置：无关文本的余弦也 0.9+，0.25 的相似度门限形同虚设，**每次召回都是满筐噪声**。

- 实测反面教材：`nomic-embed-text-v1.5`，无关词对「游乐园 vs 草莓蛋糕」余弦 **0.9935**
- 实测正面参考：`BAAI/bge-m3`，同一对 **0.4977**

**上线前必跑** `engine/tools/check_embedding.js`，它会检查维度、塌缩、词级/句级区分度。判据：无关对 < 0.85，区分度 ≥ 0.05（≥0.15 优秀）。

## 2. 维度不符 = 检索静默失效

配置里 `dim` 与向量模型真实维度不一致时，召回层会因「`vector.length !== queryVec.length`」把所有节点跳过——不报错、不抛异常，就是永远召回空。换模型（如 768→1024）后必须：改 `dim` → 跑 `rebuildVectors()` → 重启。

## 3. 捕获点要在「回复生成处」，不在「投递处」

如果挂在消息投递层，气泡拆分 / 长文本分段 / TTS 转写会把一条回复撕成 N 个碎片，抽出来的事件全是断句。正确位置是 session 事件层的 `assistant/message`（完整回复、按 `message.id` 去重——流式/用量更新会重发同一 message），`turn/end` 且 `completed` 才配对入库。出错或取消的回合两侧一起丢，否则残留的半条用户消息会和下一轮回复错误配对。

## 4. 虚构内容绝不能进图谱

角色扮演 / 场景模拟 / 剧情回合里「用户说过什么」是编的。这些内容一旦被抽成事件，就是长期记忆里最难清理的污染（用户没说过的话，系统却「记得」）。桥接层用回合的 `adoptedLifeTurn` 标记识别场景回合并整体跳过（不捕获也不召回）。如果你的宿主也有类似机制，务必接上这个闸门。

## 5. 同一引擎目录被并发打开 = 吞消息

两个回调同时首次触达同一个 chatId 时，若各自 `open` 一个引擎实例，后开的实例会覆盖前者缓冲区——那一轮对话就静默丢了。桥接层用「in-flight promise 去重」保证同目录只 open 一次。自己写集成时注意这条。

## 6. 停机不冲刷 = 最后几轮永远丢

抽取是攒批的（默认 2 轮），缓冲里永远可能有未入库的轮次。桥接在 `stop()` 里 `await close()`（触发 flush）；自己写集成时同理，进程退出前必须 close。

## 7. 网关类端点的额外 HTTP 头

某些 OpenAI 兼容网关要求自定义会话头（如 `x-session-id`），不带就 403/400，且报错信息完全不提是头的问题。`chatHeaders` 配置就是为这个准备的。另外注意：部分网关对 `curl` 放行但对某些 HTTP 客户端指纹拦截，排查时先换 curl 对照。

## 8. 「召回一直是空的」的排查顺序

1. `check_embedding.js`（塌缩/维度）
2. 日志有没有 `turn buffered`（没有 = 捕获层没工作，看 enabled 与挂钩）
3. 日志有没有 `extract_empty`（有 = LLM 抽不出事件：换更强的 chat 模型，或对话里确实没有值得记的事——问候客套本来就不该入库）
4. `stats()` 看 `pending`（卡在缓冲 = flush 没跑）

## 9. 记忆污染的长期防御

- 检索只取 top 5——库越大，单条记忆被召回的机会越稀释；噪声记忆会挤掉真记忆的槽位
- 建议做法：外源内容（爬来的网页、别人转发的资料）**不要**直接 `enqueue` 进图谱；要引入就在对话里让模型自己消化，靠抽取层的「长期记忆价值」判断过滤
- 错误记忆用 `deleteNode(id)` 删；重要记忆用 `markCustom(id)` 钉住（+0.3 分、永不衰减）

## 10. 性数量级

- 抽取：每批 2~4 次 LLM 调用（事实抽取 1 次 + 概念归纳 1 次 + 关系 0~2 次，默认只开前两个）
- 召回：每条入站消息 1 次 embed 调用 + 本地扫描（万条节点 10~30ms）
- 存储：纯文本 JSONL，一年重度使用量级在几十 MB 内
